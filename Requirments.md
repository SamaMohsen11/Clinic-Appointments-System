# 1. Requirements Classification

| Requirement ID | Original Requirement Text | Type | Classification Reason |

| R1 | A patient can view the days and times when a doctor is available. | Functional | Defines a function the system provides to patients. |

| R2 | A patient can book an appointment during an available time slot. | Functional | Defines the appointment-booking functionality provided by the system. |

| R3 | A doctor can accept or decline an appointment request. | Functional | Defines an action the system must allow doctors to perform. |

| R4 | A patient can have at most 3 upcoming appointments at any given time. | Functional | Defines a business rule the system must enforce when managing upcoming appointments. |

| R5 | Patient medical data shall be accessible only to authorized staff. | Non-Functional | Specifies a security constraint that protects sensitive medical data. |

| R6 | Available appointment times shall be displayed within 2 seconds. | Non-Functional | Specifies a performance requirement that limits the response time. |

| R7 | The application shall be usable on mobile phone screens. | Non-Functional | Specifies a usability and compatibility requirement for mobile devices. |
